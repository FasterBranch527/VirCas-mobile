## Что изменено

### Очередь с подтверждением успешного сохранения

Добавлен `core/game/RoundWriteQueue.kt`, подключён в `ui/AppViewModel.kt` вместо карты повторов и отдельного mutex.

- Checkpoint, settlement, cancellation, восстановление и reset проходят через одну FIFO-очередь.
- При ошибке операция остаётся первой в очереди. Следующая операция не обходит её.
- Возвращается `Deferred<Unit>`: подтверждение остаётся незавершённым при ошибке и завершается успешно только после успешной записи. Для новых/обновляемых контроллеров использовать `.await()`, а не `.join()` / `isCancelled` как доказательство сохранения.
- Retry повторяет ту же операцию и продолжает ту же очередь. Операции с одним ID раунда не заменяют друг друга: последовательность промежуточного банка и терминального исхода сохраняется.
- Отмена ожидающей анимации или её ticket не отменяет саму транзакцию.
- Reset отменяет подтверждения старых ожидающих операций, но ждёт завершения уже исполняющейся транзакции перед записью сброса. Ошибка старого поколения не должна блокировать новый reset.
- Поздний callback settlement, очистка RNG и освобождение блокировки Start проверяют поколение аккаунта.

Это не перевод всех операций приложения в одну транзакционную систему: begin/increase, быстрые resolver-пути, награды, продажа и DataStore reset требуют оставшихся проверок из исходного плана. Полная crash-atomicity reset по-прежнему не доказана.

В `VirCasApp.kt` существующий `RoundPersistenceGate(appViewModel)` теперь оборачивает выбор onboarding/navigation внутри `VirCasTheme`. Список маршрутов, оформление игр и компоненты самого gate не изменены.

### Регрессионные тесты и CI

Добавлены **9 JVM-тестов** `RoundWriteQueueTest.kt`:

1. Ошибка checkpoint не подтверждает сохранение, не раскрывает результат ожидающему контроллеру и не пропускает settlement.
2. Несколько checkpoint одного раунда не заменяют друг друга.
3. Повторный Retry не повторяет уже успешную операцию.
4. Отмена анимации не отменяет сохранение.
5. Отмена ticket не даёт следующей операции обойти транзакцию.
6. Reset отбрасывает ожидающие старые операции и отменяет их подтверждения.
7. Reset ждёт исполняющуюся транзакцию и подавляет её устаревшую ошибку.
8. Повторная ошибка Retry сохраняет блокировку.
9. Закрытие владельца отменяет ожидающие подтверждения после окончания текущей транзакции.

Android CI дополнен сборкой `assembleDebug assembleDebugAndroidTest` и сохранением JVM-отчётов/тестовых APK. **Компиляция инструментальных тестов не является их запуском.** Триггеры, release-signing и зависимости не изменены.
